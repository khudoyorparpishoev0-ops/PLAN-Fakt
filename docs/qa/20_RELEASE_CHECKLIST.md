# Чек-лист выпуска

Перед обновлением боевого сервера.

## Обязательно

- [ ] `npm ci && npm run build` — фронтенд собирается
- [ ] `cd server && npm ci && npm run prisma:generate && npm run build`
- [ ] `npx tsc --noEmit` на обеих сторонах — без ошибок
- [ ] Пять регресс-проверок зелёные:
      `check:expense`, `check:planfact`, `check:currency`, `check:export`, `check:audit`
- [ ] Свежая резервная копия снята **до** обновления: `sudo /opt/app/backup-db.sh`
- [ ] Копия разворачивается: `sudo /opt/app/app/deploy/check-restore.sh`

## Развёртывание

Команды набирать **полным путём**: ни `check-service.sh`, ни `check:audit`
в PATH не лежат — это файл в репозитории и npm-скрипт внутри контейнера.

- [ ] `sudo sh /opt/app/app/deploy.sh`
- [ ] `sudo sh /opt/app/app/deploy/check-service.sh` — 15 проверок, только чтение
- [ ] Регресс на боевой базе (**создаёт данные с пометкой `TEST-QA` и убирает
      их за собой**; отправленные заявки удалить нельзя — они уходят отказом):

```sh
cd /opt/app
for c in expense planfact currency export audit; do
  sudo docker compose exec -T backend npm run check:$c
done
```

**Пароли.** Проверки читают `SEED_PASSWORD_ADMIN`, `SEED_PASSWORD_DIRECTOR` и
`SEED_PASSWORD_ACCOUNTANT`. На свежей установке они лежат в `/opt/app/.env` и
подходят. Но система требует сменить временный пароль при первом входе —
значит **на работающем сервере значения в `.env` устарели**, и вход отклоняется
с 401. Тогда пароли передаются явно:

```sh
sudo docker compose exec -T \
  -e SEED_PASSWORD_ADMIN='…' -e SEED_PASSWORD_DIRECTOR='…' \
  -e SEED_PASSWORD_ACCOUNTANT='…' backend npm run check:audit
```

Пароли попадут в историю оболочки — либо начните команду с пробела, либо
смените их после проверки.

**Лучше так не делать.** Проверки создают записи в боевой базе, а отправленную
заявку система удалять не даёт — две-три строки `TEST-QA` останутся в истории
со статусом «Отклонено». Место этих проверок — тестовая копия базы, а на
боевом сервере достаточно `check-service.sh` (только чтение) и осмотра
интерфейса.

- [ ] В браузере Ctrl+Shift+R

## После обновления убедиться

- [ ] Вход тремя ролями работает
- [ ] Заголовки безопасности пришли: `curl -sD- http://СЕРВЕР/api/health -o /dev/null`
      → `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, без `X-Powered-By`
- [ ] Перебор пароля упирается в 429 после восьми попыток
- [ ] Загрузка настоящего PDF проходит, переименованного `.exe` — нет
- [ ] Сделка с плановой операцией показывает верный долг
- [ ] План-факт открывается и совпадает с журналом

## Не выпускать, если

- падает хоть одна из пяти регресс-проверок;
- план-факт расходится с журналом;
- резервная копия не разворачивается;
- сборка не проходит;
- появился любой дефект уровня P0 или P1.

## Известные оговорки этого выпуска

Не блокируют выпуск, но должны быть в курсе директор и администратор:

- перевод между счетами через интерфейс не оформляется (FIN-003);
- переплата и поставка сверх заказа проходят без предупреждения (FIN-004);
- Excel по умолчанию не включает архивные проекты, экран включает (EXP-001);
- refresh-токен многоразовый; после блокировки сотрудника его доступ живёт
  до 15 минут (SEC-004);
- шрифты грузятся с серверов Google (UI-001).
