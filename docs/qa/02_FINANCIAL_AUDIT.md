# Финансовый аудит

## Хранение денег

Суммы — целые дирамы (`BigInt`, 1 сомони = 100 дирам). Проверено на живом API:

| Введено | Возвращено | Итог |
| --- | --- | --- |
| 0,01 | 0,01 | ok |
| 0,10 | 0,1 | ok |
| 0,99 | 0,99 | ok |
| 1,01 | 1,01 | ok |
| 0,30 | 0,3 | ok (0.1 + 0.2 не всплывает) |
| 1 234,56 | 1234.56 | ok |
| 1 000 000,99 | 1000000.99 | ok |
| 1 000 000 000 | 1000000000 | ok |
| 1e15 | **было принято** | дефект FIN-002, исправлен |

Поиск `parseFloat` / `Number()` по денежным путям: пересчёт валют идёт через
`Prisma.Decimal`, в базу пишется `BigInt`. Единственное место с плавающей
арифметикой — `positionTotal` в сделках: `qty × priceDirams` со скидкой в
процентах считается числами с плавающей точкой и округляется. Для количеств и
цен реального масштаба ошибка не проявляется; отмечено как P3-наблюдение.

## Остатки счетов

Независимая проверка формулой «входящий остаток + доходы − расходы»:

```sql
select sum(opening_dirams)/100.0
     + sum(case when type='in' then amount_tjs_dirams
                when type='out' then -amount_tjs_dirams else 0 end)/100.0
```
База: **753 294,50**. API `metrics.cashTotal`: **753 294,50**. Совпало.

Неподтверждённая (плановая) операция на 77 777 TJS остаток не изменила —
проверено до и после создания.

## Переводы между счетами

Перевод не должен трогать ни прибыль, ни общий остаток. Проверить сценарий
«касса → банк» через API **не удалось**: `POST /operations` не принимает тип
`move` (422 `type: in | out`). Дефект FIN-003, описан в «Осталось».

Косвенно правило соблюдается: в план-факт факт отбирается по `type in ('in','out')`,
так что существующие переводы из демо-данных в расходы не попадают —
подтверждено `check:planfact`, сценарий 3.

## Закупки: оплаты, долг, поставки

| Сценарий | Ожидание | Факт |
| --- | --- | --- |
| 10 шт × 1 000 | итог 10 000 | ok |
| оплаты 3 000 + 2 000 | оплачено 5 000 | ok |
| плановая операция 5 000 | долг не меняется | **было «оплачено 10 000»** → исправлено (FIN-001) |
| оплата 999 000 сверх заказа | видна как переплата или отказ | принимается молча — FIN-004 |
| поставки 4 + 6 из 10 | поставлено 10 000 | ok |
| поставка 11-й штуки | отказ или пометка | принимается молча — FIN-004 |
| списать со склада больше остатка | отказ | 422 ok |

## Финансовый результат

Прибыль считается как доходы минус расходы по подтверждённым операциям;
переводы в неё не входят (см. выше). Сверено на демо-данных: план-факт API и
прямая SQL-агрегация дают одинаковый факт расходов **3 964 633,50** за 2026 год.
