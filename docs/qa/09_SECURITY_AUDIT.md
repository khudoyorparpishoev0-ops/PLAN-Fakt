# Аудит безопасности

## Аутентификация

| Проверка | Результат |
| --- | --- |
| Пароли — bcrypt (10 раундов) | ok, открытым текстом нигде не хранятся |
| Неверный пароль → 401 | ok, ответ не различает «нет пользователя» и «неверный пароль» |
| Несуществующий адрес → 401, не 404 | ok |
| Пустые поля → 422 | ok |
| Адрес в верхнем регистре | ok |
| Адрес с пробелами | **было 422** → исправлено (UX-004) |
| Временный пароль требует смены | ok: до смены любой запрос → 403 `password_change_required` |
| Перебор пароля | **не ограничивался** → исправлено (SEC-001): 8 неудач → 429 на 5 минут |

## Токены

| Проверка | Результат |
| --- | --- |
| Без токена → 401 | ok |
| Мусорный токен → 401 | ok |
| Чужая подпись → 401 | ok |
| `Bearer` без значения → 401 | ok |
| Refresh-токен не работает как access | ok |
| Refresh выдаёт новую пару | ok |
| **Повторное использование refresh** | **принимается** — ротации нет, SEC-004 |
| Заблокированный: вход | 401 ok |
| Заблокированный: refresh | 401 ok |
| Заблокированный: уже выданный access | **работает до 15 минут**, SEC-004 |

## IDOR

Создан второй бухгалтер, у него своя заявка. Проверено:

| Действие первого бухгалтера | Результат |
| --- | --- |
| Видит чужую заявку в списке | нет |
| `PATCH /requests/:чужой` | 404 |
| `DELETE /requests/:чужой` | 404 |
| Скачать вложение чужой заявки | 404 |
| Директор видит заявки обоих | да, как и задумано |

## Инъекции

- **SQL.** Весь доступ к базе — через Prisma с параметрами. Поиск по
  `$queryRawUnsafe` / `$executeRawUnsafe` дал ноль совпадений.
- **XSS.** Заявка с именем `<img src=x onerror=alert(1)>` создана через API и
  открыта в браузере: диалог не появился, текст показан как есть. React
  экранирует по умолчанию, `dangerouslySetInnerHTML` в коде нет.
- **Excel-формулы.** Проверено на файле: строки `=SUM(A1:A2)`, `+CMD`, `-1+1`,
  `@SUM(1)` попадают в `sharedStrings.xml` как текст (`<si><t>`), элементов
  `<f>` в листе ноль. XLSX, в отличие от CSV, текстовую ячейку формулой не
  делает — **уязвимости нет**, экранирование не требуется.
- **Массовое присвоение.** `ValidationPipe({ whitelist: true })` срезает поля,
  которых нет в DTO: подсунуть `status: 'approved'` при создании заявки нельзя.

## Загрузка файлов

| Проверка | Результат |
| --- | --- |
| Тип по содержимому, а не по заголовку | **было по заголовку** → исправлено (SEC-003) |
| Исполняемый файл под видом PDF | 422 |
| Настоящий PDF с чужим `Content-Type` | принят, тип распознан |
| Ограничение 10 МБ | ok (multer `limits.fileSize`) |
| Имя файла в ключе хранилища | не используется: ключ — 12 случайных байт + расширение, обход каталогов через `../` невозможен |

## Заголовки и раскрытие внутренностей

| Заголовок | До | После |
| --- | --- | --- |
| X-Content-Type-Options | нет | `nosniff` |
| X-Frame-Options | нет | `DENY` |
| Referrer-Policy | нет | `no-referrer` |
| Content-Security-Policy | нет | задана на статике |
| X-Powered-By | `Express` | снят |
| HSTS | нет | **осознанно нет** — включать вместе с HTTPS |

CORS не настроен вовсе, и это правильно: фронтенд и API за одним nginx,
заголовка `Access-Control-Allow-Origin` в ответах нет.

Ошибки не раскрывают внутренностей: 404 отдаёт `{"error":{"code":"not_found",
"message":"Операция не найдена"}}` — ни стека, ни строки подключения. Нечисловой
id → 400, не 500.

## Журнал действий

По 50 последним записям: паролей, токенов и временных паролей нет —
записывается только факт («сброшен пароль пользователю X»). У каждой записи
есть автор, время, сущность и действие. Эндпоинта удаления аудита не
существует (`DELETE /audit/1` → 404), сам журнал доступен только администратору.
