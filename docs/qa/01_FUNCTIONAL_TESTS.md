# Функциональные проверки

Сводка того, что выполнялось. Подробности — в тематических файлах.

## Автоматические регресс-проверки (в репозитории)

| Команда | Утверждений | Что сторожит |
| --- | --- | --- |
| `npm run check:expense` | 5 | расход появляется по оплате, не по приёмке |
| `npm run check:planfact` | 17 | деньги и отчёт сходятся; пять сценариев заказчика |
| `npm run check:currency` | 18 | справочник, курсы, пересчёт в сомони |
| `npm run check:export` | 25 | шесть правил формата Excel |
| `npm run check:audit` | 23 | дефекты, найденные этим аудитом |

Все запускаются против **живого API** и убирают за собой созданные данные.

## Сценарии из задания, выполненные вручную

- Вход тремя ролями, неверный пароль, пустые поля, регистр и пробелы в адресе.
- Обязательная смена временного пароля: до смены любой запрос → 403.
- Полный путь заявки: создание бухгалтером → решение директора → плановая
  операция → сторнирование.
- Пять одновременных одобрений одной заявки.
- Встречные решения «одобрить» и «отклонить» одновременно.
- Сделка: позиции, частичные оплаты, поставки, попытка перепоставки и переплаты.
- Склад: приход по поставке, попытка списать больше остатка.
- Валюта: операция без курса, курс на дату, изменение курса задним числом.
- 10 000 операций: отклик списков, отчёта и выгрузки.
- Резервная копия и её восстановление во временную базу.
- Миграции с нуля и повторно.
