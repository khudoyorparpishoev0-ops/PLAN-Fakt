# Аудит заявок и согласований

## Жизненный цикл

Статусы: `draft` → `sent` → `review` → `approved` / `rejected`.
Переходы проверяются на сервере:

| Из | Куда можно |
| --- | --- |
| draft | (директору не показывается — сначала отправка автором) |
| sent | review, approved, rejected |
| review | approved, rejected |
| approved | **никуда** — только сторнирование |
| rejected | никуда (автор правит и отправляет заново) |

Повторное одобрение одобренной заявки → 422 `request_immutable`.

## Двойное нажатие «Одобрить»

Пять одновременных запросов на одобрение одной заявки: создана **одна**
плановая операция. Идемпотентность обеспечена уникальным `external_ref`
вида `req:<номер>` и `upsert` — операция не задваивается.

## Гонка «одобрить / отклонить»

Два встречных решения, отправленных одновременно: итог согласован — заявка
`approved`, плановая операция одна. Рассогласования «отклонено, но операция
создана» не наблюдалось.

Оговорка честности: проверка статуса выполняется **до** транзакции, так что
теоретическая гонка возможна на более медленной базе. Наблюдаемого дефекта
нет; при желании закрывается пересчётом статуса внутри транзакции.

## Валидация формы заявки

| Ввод | Результат |
| --- | --- |
| без суммы | 422 «Укажите сумму» |
| отрицательная сумма | 422 |
| ноль | 422 |
| сумма за пределом точности | 422 (исправление FIN-002) |
| неизвестная валюта | 422 |
| валюта без курса | принимается, предупреждение в форме |
| поездка без фото одометра | 422 |
| авто-расход от 100 TJS без чека | 422 |
| разметка и emoji в наименовании | принимаются, выводятся текстом |

## Правка и удаление

Автор правит только `draft` и `rejected`; удаляет только `draft`.
Отправленную заявку удалить нельзя — она уходит из очереди отказом.
Чужую заявку не видно и не изменить (404).

## Сторнирование

Сторно не удаляет ни заявку, ни операцию: создаётся обратная запись
`req:<номер>:storno`, заявка остаётся одобренной с отметкой. В план-факте пара
схлопывается в ноль, строка получает статус «Сторнировано».

## Поездки

100 км × ставка 3 = 300 TJS. Ставка берётся на момент решения и остаётся в
операции навсегда — после удвоения ставки операция не изменилась.

**Дефект QA-003 (исправлен):** при нулевой ставке заявка одобрялась и давала
расход на 0 сомони. Теперь 422 с указанием, где задать ставку.

**Остаётся FIN-005:** кабинет показывает суммы поездок по текущей ставке, а не
по той, что записана в операции.

## Аудит решений

По каждой заявке видно: автор, дата, кто решил, когда, комментарий отказа,
кто сторнировал. Всё пишется в `audit_logs` — 402 записи на демо-базе.
