## Три главных правила системы — проверены отдельно

1. **Расход появляется по оплате, а не по приёмке.** Поставка создаёт только
   складские движения; факт растёт от выплаты. Проверено `check:expense` и
   вручную по коду.
2. **План-факт считается из живых данных.** Сверено с прямой SQL-агрегацией:
   факт расходов 3 964 633,50 в базе и столько же в API. Строка с фактом без
   плана показывается со статусом «План не указан».
3. **Валюта учёта одна, платёж — в любой.** Операция хранит курс на свою дату;
   изменение справочника курсов историю не переписывает (проверено:
   операция 01.08 осталась 1050 TJS после добавления курса на 05.08).
