# IT-HONA · «Финансы: План-Факт» — что это и как устроено

Внутренняя система управления финансами **ООО «IT-HONA»** (Душанбе, Худжанд):
интеграция и монтаж инженерных систем. Заменяет учёт в Excel и переписку в
мессенджерах: заявки на оплату, решения директора, журнал операций, план и
факт по статьям и проектам, склад и закупки, выгрузки в Excel.

Учёт ведётся в **сомони (TJS)**; операции и заявки принимаются в любой валюте
мира и пересчитываются в сомони по курсу на дату операции.

---

## 1. Кто чем занят в системе

Три роли, вход по e-mail и паролю; права проверяются **на сервере** — чужой
эндпоинт возвращает 403, а не просто прячет кнопку.

| Роль | Что делает | Что видит |
| --- | --- | --- |
| **Бухгалтер** (`accountant`) | подаёт заявки на оплату, поездку, расход на авто; прикладывает счета и чеки; ведёт свои проекты и задачи | **кабинет**: только свои заявки, свои проекты, история, задачи |
| **Директор** (`director`) | принимает решения по заявкам (одобрить / отклонить / сторнировать), ведёт операции, план, закупки, склад, справочники | **панель** целиком, кроме управления пользователями |
| **Администратор** (`admin`) | выдаёт права, сбрасывает пароли, задаёт курсы валют и настройки, смотрит аудит-лог | **панель** целиком + пользователи и настройки |

Интерфейс выбирается по роли: бухгалтер попадает в кабинет, директор и
администратор — в панель (`src/App.tsx`).

## 2. Главная бизнес-логика

Три правила, на которых держится вся система. Они закрыты регресс-тестами,
потому что ломаются молча.

### Расход — это оплата, а не приёмка

Факт расхода появляется **в момент выплаты поставщику**, а не когда товар
приняли на склад. Поставка создаёт только складские движения. Благодаря
этому План-Факт сходится с банковской выпиской.

| Событие | Что создаётся | Влияет на План-Факт |
| --- | --- | --- |
| Поставка по сделке | складские движения | нет |
| Одобрение заявки | плановая операция расхода | план, не факт |
| Выплата поставщику | фактическая операция | **да, это факт** |

Проверка: `npm run check:expense`.

### План-Факт считается из живых данных

Строка отчёта — это агрегат по паре **(статья, проект)**: план из плановых
строк периода, факт из подтверждённых операций. Статья с фактом, но без плана
всё равно показывается («План не указан»): скрыть её значило бы потерять
реальный расход. Переводы между счетами и неподтверждённые операции в факт не
входят — по тому же правилу, что и остаток счёта.

Проверка: `npm run check:planfact` (5 сценариев заказчика).

### Валюта учёта одна, валюта платежа любая

Операция хранит сумму в своей валюте **и** сумму в сомони по курсу на свою
дату. Итоги, отчёты и остатки складывают только сомони. Операция без курса не
сохранится (422): подставить единицу молча нельзя — «1000 USD» превратилось бы
в 1000 сомони.

Проверка: `npm run check:currency`.

## 3. Экраны

### Кабинет бухгалтера (`src/cabinet`)

| Экран | Что делает |
| --- | --- |
| Заявки на оплату | форма заявки (проект, сумма и валюта, наименование, контрагент, срочность, документ) + свои последние заявки |
| Заявки на машину | поездка по километрам и расход на авто (бензин, ремонт, мойка, штраф, запчасти) |
| Список всего / История | все заявки с фильтрами, диаграмма по видам, правка черновиков и отклонённых |
| Проекты | свои проекты: одобрено, ждёт решения |
| Мои задачи | задачи со статусами и сроками |
| Уведомления | решения по заявкам, задачи |

На телефоне обе формы заменяет единая форма с крупным полем суммы; подпись
кнопки называет недостающее поле, а не остаётся серой.

### Панель директора и администратора (`src/admin`)

| Экран | Что делает |
| --- | --- |
| Заявки на утверждение | очередь решений: срочные наверху, карточка с контрагентом, вложением и влиянием на план проекта |
| Показатели | деньги, задолженности, кассовый разрыв, доходы и расходы за период |
| План-Факт | отчёт по статьям: результат, группы, водопад отклонений, предупреждение о статьях без факта, настраиваемые пороги статусов |
| Операции | журнал: серверные фильтры, поиск, пагинация, массовые действия, карточка операции, вложения; формы дохода и расхода |
| Планирование | годовая сетка планов по статьям и месяцам |
| Проекты | карточки проектов, сводка, входящие остатки, архив |
| Закупки | сделки: позиции, частичные оплаты, поставки, файлы |
| Склад | остатки и движения товаров |
| Клиенты | контрагенты с оборотами |
| Задачи | задачи и исполнители |
| Справочники | статьи, счета, контрагенты, товары, услуги, юрлица |
| Пользователи | создание, роли, блокировка, сброс пароля |
| Настройки | компания, ставка км, курсы валют, пороги План-Факта, выгрузки по расписанию, аудит-лог |
| Экспорт | выгрузка в Excel: набор колонок, архивные проекты, регулярные выгрузки |

## 4. Технологии

| Слой | Что |
| --- | --- |
| Интерфейс | Vite + React 18 + TypeScript, инлайн-стили на CSS-переменных дизайн-системы (`src/tokens.css`), без UI-библиотек |
| API | NestJS 10 + Prisma 5 + PostgreSQL 16, JWT (access + refresh), guard'ы ролей |
| Файлы | MinIO (S3) с запасным вариантом — локальный каталог |
| Excel | ExcelJS: журнал, План-Факт, проекты; выгрузки по расписанию |
| Развёртывание | Docker Compose (postgres, minio, backend, frontend) + системный nginx |

**Деньги хранятся в дирамах** (1 сомони = 100 дирам) целыми числами `BigInt` —
никаких `float` в суммах. Курсы валют — точная десятичная арифметика.
**Удаление всегда мягкое** (`deleted_at`), все изменения пишутся в `audit_logs`.

Объём: ~20 000 строк TypeScript в 141 файле репозитория, 26 моделей базы,
13 миграций, 75 эндпоинтов API.

## 6. Как запустить

**Разработка.** Нужны Node 20+ и PostgreSQL.

```bash
# API
cd server
cp .env.example .env          # прописать DATABASE_URL и JWT_SECRET
npm ci && npm run prisma:generate
npm run migrate:deploy && npm run seed
npm run start:dev             # http://localhost:3000/api

# интерфейс
npm ci && npm run dev         # http://localhost:5173
```

**Сервер.** Одна команда, идемпотентная — повторный запуск обновляет
развёрнутое:

```bash
sudo sh deploy.sh
```

Скрипт ставит зависимости, обновляет код, дописывает переменные окружения и
сервисы в compose, собирает контейнеры, применяет миграции, настраивает nginx и
ежедневные резервные копии. Проверить состояние:

```bash
sh /opt/app/app/deploy/check-service.sh
```

**Перед боевым запуском** демо-данные убираются и больше не возвращаются:

```bash
docker compose exec backend npm run clean:demo
```

Подробности выкладки, эксплуатации и всех принятых решений — в
[`docs/DEPLOY.md`](DEPLOY.md).

## 7. Как проверяется работа

Не «код написан», а «система себя ведёт правильно»: четыре регресс-теста
работают против **живого API** и убирают за собой созданные данные.

```bash
cd server
npm run check:expense     # расход появляется по оплате
npm run check:planfact    # деньги и отчёт сходятся, 5 сценариев
npm run check:currency    # валюты, курсы, пересчёт в сомони
npm run check:export      # формат выгрузок Excel
```

Плюс `tsc --noEmit` и сборка с обеих сторон, проверки интерфейса в браузере
(Playwright) на 1440, 375 и 360 пикселях.
