Модуль «Финансы: План-Факт» и кабинет бухгалтера
Заказчик: IT-HONA LLC Версия: 1.0 от 29.07.2026 Основание: утверждённый дизайн-прототип
1. Общие сведения
  • Цель: учёт доходов и расходов по проектам в разрезе «план — факт», согласование заявок сотрудников директором.
  • Платформа: веб-приложение (десктоп + адаптив под телефон).
  • Язык: русский. Базовая валюта: TJS (сомони); справочно USD, EUR, RUB, CNY с курсом на дату операции.
  • Состав: админ-панель «Финансы План-Факт» и личный кабинет операционного бухгалтера.
2. Роли и права

3. Админ-панель «Финансы План-Факт»
3.1. План-Факт (дашборд)
  • Шапка: заголовок раздела, подпись «месяц · TJS», переключатель «Компьютер / Телефон», селектор юрлица «IT-HONA LLC», колокольчик с бейджем непрочитанных.
  • Панель периода: сегмент-контрол День / Неделя / Месяц / Квартал / Год + фильтры «Проект», «Статус», «Валюта» + поиск. Выбор периода пересчитывает все карточки и таблицы без перезагрузки.
  • KPI-карточки (4): План, Факт, Выполнение % (прогресс-бар), Отклонение/Осталось. Формат чисел: пробел-разделитель тысяч, tabular-nums, код валюты 11–12px.
  • Статусы отклонений по порогам недорасхода: 0% — «По плану» (серый), ≤5% — «В норме» (зелёный), 5–20% — «Экономия» (зелёный), >20% — «Проверить план» (жёлтый). Перерасход — красный.
  • Таблица план-факт по статьям: иерархия статей с раскрытием, колонки План / Факт / Откл. / % / статус-бейдж; клик по строке — детализация операций статьи.
3.2. Операции (единый журнал)
  • Панель фильтров слева 236px, сворачивается в узкую полосу 38px с иконкой воронки; состояние запоминается на пользователя.
  • Блоки фильтров: тип операции — чекбоксы Поступление / Выплата / Перемещение / Начисление; дата оплаты — Подтверждена / Не подтверждена + поле периода; параметры — выпадающие мультиселекты Юрлица и счета, Контрагенты, Статьи учёта, Проекты; диапазон «Сумма от / до». Все фильтры комбинируются по И, применяются мгновенно.
  • Колонки таблицы: ☐ чекбокс массовых действий · Дата (сортировка ▾ по умолчанию — новые сверху) · Счёт · Тип (← зелёная стрелка приход, → красная расход) · Контрагент · Статья: название + тег [Доходы]/[Расходы] + серое примечание второй строкой · Проект · Сумма: +/− с цветом, десятичные «,00 TJS», иконка 💬 при комментарии.
  • Группировка строк: «Сегодня» (или «Сегодня нет операций») и «Вчера и ранее». Клик по строке — карточка операции; чекбоксы включают панель массовых действий (подтвердить, удалить, сменить проект).
  • Поиск сверху ищет по контрагенту, статье, примечанию, сумме. Кнопка «⋯» — экспорт и настройка колонок.
3.3. Проекты
  • Виды списка: по проектам / по группам проектов; показатели: прибыль начислением, прибыль кассовым методом, движение денег; опция «Показывать план».
  • Статусы: Плановый (автоматически), В работе (автоматически), Завершён (вручную); фильтр по датам начала/окончания, архив; итоговая строка по выборке.
  • Действия: карточка проекта по клику, архивирование, редактирование, удаление, экспорт в Excel, группировка.
3.4. Справочники
  • Подменю: Контрагенты, Учётные статьи, Мои счета, Мои юрлица — Товары, Услуги (со счётчиками записей).
  • Учётные статьи: вкладки Доходы / Расходы / Активы / Обязательства / Капитал; иерархия с подстатьями («+»), системные статьи с замком (не удаляются), меню действий.
  • Остальные справочники: список с поиском и кнопкой добавления.
3.5. Настройки
  • Профиль компании, пользователи и учётные записи, права по ролям.
4. Кабинет операционного бухгалтера
4.1. Заявки на оплату
  • Форма: 1) Проект — селект из активных проектов, обязательное; 2) Сумма — число > 0, до 2 знаков после запятой, + валюта (TJS по умолчанию); 3) Наименование — текст 3–200 символов, обязательное; 4) Документ — JPG/PNG/PDF до 10 МБ, опционально.
  • Кнопка «Отправить на утверждение Директору» активна только при валидной форме; после отправки — тост «Заявка №… отправлена», форма очищается, запись появляется первой строкой со статусом «Отправлено» без перезагрузки.
  • Таблица «Мои последние заявки» (10 последних): Дата · Проект · Наименование · Сумма · Статус (свой) · Директор (второй бейдж). Полный список — в «Список всего / История».
4.2. Заявки на машину
  • Две вкладки-сегмента: «Заявка на поездку» / «Расходы на авто», под каждой — своя форма и своя таблица «Мои…».
  • Поездка: Проект (обязательное) · Цель поездки (текст 3–120) · Км — целое число > 0 + обязательное фото одометра (JPG/PNG до 10 МБ) · Контрагент (текст/выбор из справочника).
  • Расход на авто: Проект · Категория — селект Бензин / Ремонт / Мойка / Штраф / Запчасти · Сумма > 0 + валюта · Чек (обязателен для сумм ≥ 100 TJS).
4.3. Список всего / История
  • 4 карточки-фильтра: Проект · Тип (Оплата / Поездка / Авто) · Период (месяц / квартал / год / всё время) · Статус; применяются к реестру и графикам одновременно.
  • Мини-графики: пончик «Расходы по категориям» (доли Оплаты / Поездки / Авто) и линия «Статистика по месяцам» — только по своим заявкам.
  • Главный реестр, вкладки Оплаты / Поездки / Авто. Колонки: ID (кликабелен) · Дата · Проект · Наименование · Сумма/Км · Директор (статус) · Действия: 👁 просмотр (карточка заявки с историей статусов), 📷 фото км, 📄 документ/чек, 🗑 удаление — только «Черновик».
4.4. Проекты
  • Список проектов с ответственным, числом моих заявок, суммами «Одобрено» / «Ждёт решения» и статусом. Чужие финансовые данные скрыты.

8. Бизнес-правила и расчёты
  • Отклонение = факт − план; % выполнения = факт / план. Пороги недорасхода: 0% «По плану», ≤5% «В норме», 5–20% «Экономия», >20% «Проверить план».
  • Статус проекта: «Плановый» — нет фактических платежей; «В работе» — есть факт; «Завершён» — только вручную. Автопересчёт при каждой операции.
  • Заявка после отправки редактируется автором только в статусе «Черновик» / «Отклонено»; одобрение директора создаёт плановую операцию расхода по проекту.
  • Мультивалютность: суммы хранятся в валюте операции + курс на дату; агрегаты считаются в TJS.
  • Удаление системных статей и справочников, на которые есть ссылки, запрещено (только архив).
  • Права: бухгалтер видит только свои заявки и агрегаты по ним; полные суммы проектов — админ/директор.
9. API (эскиз, REST/JSON)
  • GET/POST /api/operations — фильтры: type[], confirmed, date_from/to, account, contragent, article, project, amount_min/max, q
  • GET/POST/PATCH /api/projects, GET /api/projects/:id/summary (план, факт, отклонение по статьям), GET /api/projects.xlsx
  • CRUD /api/articles, /api/contragents, /api/accounts, /api/entities, /api/goods, /api/services
  • POST /api/requests (+ multipart вложения) · PATCH /api/requests/:id/status (director) · GET /api/requests?kind=&status=
  • Auth: JWT, роли в токене; все списки — пагинация limit/offset (default 50), сортировка sort=field:dir; ошибки — {"error":{"code","message","field?"}} c HTTP 400/403/404/422.
Пример: POST /api/requests
{"kind":"payment","project_id":12,"name":"Оплата хостинга за июль 2026",
 "amount":1200.00,"currency":"TJS","attachments":["file_8f2a"]}
→ 201 {"id":101,"status":"sent","director_status":"pending","created_at":"2026-07-29T10:42:00+05:00"}
10. Нефункциональные требования
  • Отклик списков ≤ 300 мс при 10 000 операций; пагинация серверная.
  • Вложения: JPG/PNG/PDF до 10 МБ, хранение в объектном хранилище, превью в UI.
  • Аудит-лог изменений (кто, что, когда) для операций, заявок, справочников.
  • Адаптив от 360px; целевые браузеры — Chrome/Safari/Edge последних 2 версий.
11. Этапность и приёмка
  • Этап 1 (текущий прототип): План-Факт, Показатели, Операции, Проекты, Справочники, Пользователи/Настройки, кабинет бухгалтера.
  • Этап 2: Задачи, Планирование, Закупки, Склад, Клиенты; уведомления; выгрузки по расписанию.
  • Критерии приёмки: пиксельное соответствие прототипу на 1280/360px; сквозной сценарий «бухгалтер создал заявку → директор одобрил → плановая операция появилась в журнале и в план-факте проекта»; фильтры журнала работают комбинированно; экспорт Excel открывается без ошибок.
